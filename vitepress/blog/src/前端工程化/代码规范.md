# 代码规范

## Prettier

> Prettier 用于格式化代码，为团队提供约束，避免因为代码格式问题带来代码更新或者冲突

基于 `monorepo` 添加 prettier

- 1、安装 prettier

`pnpm add prettier -D -w`

- 2、创建 .prettierrc.js

```js
// @see: https://prettier.io/docs/en/options

module.exports = {
  // 指定最大换行长度
  printWidth: 120,
  // 缩进制表符宽度 | 空格数
  tabWidth: 2,
  // 使用制表符而不是空格缩进行 (true：制表符，false：空格)
  useTabs: false,
  // 结尾使用分号 (true：有，false：没有)
  semi: false,
  // 使用单引号 (true：单引号，false：双引号)
  singleQuote: true,
  // 多行时尽可能打印尾随逗号 可选值"<none|es5|all>"
  trailingComma: 'es5',
}
```

- 3、集成 vscode

在根目录下创建 `.vscode` 目录，在创建 `settings.json` 文件，配置如下。可以在编辑文件时，保存触发执行 prettier

```json
{
  "editor.defaultFormatter": "esbenp.prettier-vscode",
  "editor.formatOnSave": true
}
```

- 4、集成到 scripts

在 package.json 的 scripts 中添加 prettier 命令来格式化全部文件。

```json
{
  "scripts": {
    "prettier": "prettier --write ."
  }
}
```

## ESlint

> 用于约束，检测可能存在的 js 问题。

- 1、安装依赖
  
```sh
pnpm add -D -w eslint eslint-config-prettier eslint-plugin-vue globals typescript-eslint

// 融合 prettier vue typescript
```

- 2、创建 `eslint.config.js` 文件, 参考 [eslint-plugin-vue guide](https://eslint.vuejs.org/user-guide/#example-configuration-with-typescript-eslint-and-prettier)

eslint > 9.x 是 `eslint.config.js`，如果是 8.x 是 `.eslintrc.js` ，写法不一样。

```js
import eslint from '@eslint/js'
import eslintConfigPrettier from 'eslint-config-prettier'
import eslintPluginVue from 'eslint-plugin-vue'
import globals from 'globals'
import typescriptEslint from 'typescript-eslint'

export default typescriptEslint.config(
  { ignores: ['*.d.ts', '**/coverage', '**/dist'] },
  {
    extends: [
      eslint.configs.recommended,
      ...typescriptEslint.configs.recommended,
      ...eslintPluginVue.configs['flat/recommended'],
    ],
    files: ['**/*.{ts,vue}'],
    languageOptions: {
      ecmaVersion: 'latest',
      sourceType: 'module',
      globals: globals.browser,
      parserOptions: {
        parser: typescriptEslint.parser,
      },
    },
    rules: {
      // 通用
      'no-var': 'error', // 要求使用 let 或 const 而不是 var
      indent: ['error', 2], // 要求使用 2 个空格缩进
      quotes: ['error', 'single'], // 要求使用单引号
      semi: ['error', 'never'],
      // typescript 规则
      '@typescript-eslint/no-explicit-any': 'off', // 不允许使用 any
      '@typescript-eslint/no-unused-vars': 'error', // 不允许未使用的变量
      '@typescript-eslint/no-empty-interface': 'error', // 不允许使用空接口
      // vue3 规则
      'vue/component-name-in-template-casing': ['error', 'PascalCase'], // 要求组件名称以 PascalCase 格式命名
      'vue/no-mutating-props': 'error', // 不允许修改 props
      'vue/v-bind-style': 'error', // 要求使用 : 而不是 v-bind
      'vue/v-on-style': 'error', // 要求使用 @ 而不是 v-on
      'vue/no-unused-vars': 'error', // 不允许未使用的变量
    },
  },
  eslintConfigPrettier
)
```

- 3、集成到 vscode 

在 `settings.json` 中添加配置

```json
"eslint.validate": ["javascript", "javascriptreact", "typescript", "typescriptreact", "vue"],
"editor.codeActionsOnSave": {
  "source.fixAll.eslint": "explicit"
}
```

- 4、集成到 scripts

```json
{
  "scripts": {
    "lint:fix": "eslint . --ext .js,.vue,.ts --fix"
  }
}
```

## Commitlint

- 1、安装依赖

```sh
pnpm add -w -D @commitlint/config-conventional @commitlint/cli
```
- 2、新建文件 `commitlint.config.js` , 如果是 module ，则修改为 `.cjs`
  
```sh
echo "export default { extends: ['@commitlint/config-conventional'] };" > commitlint.config.js
```
- 3、安装 husky

```sh
// 安装
pnpm add -w -D husky
// 初始化
pnpm husky install
// 创建 commit-msg 文件
echo "pnpm exec commitlint --edit \$1" > .husky/commit-msg
```

- 4、测试：

```sh
git commit -m 'xxx:xxx'
⧗   input: xxx:xxx
✖   subject may not be empty [subject-empty]
✖   type may not be empty [type-empty]

✖   found 2 problems, 0 warnings
ⓘ   Get help: https://github.com/conventional-changelog/commitlint/#what-is-commitlint

git commit -m 'feat: add commitlint commit-msg'    // 成功
```

## lint-staged

- 1、安装

```sh
pnpm add -w -D lint-staged
```
- 2、跟 package.json 添加 lint-staged

```json
"lint-staged": {
  "*.{vue,js,jsx,ts,tsx}": [
    "pnpm run format",
    "pnpm run lint:fix"
  ]
}
```
**Monorepo 项目：**

monorepo 项目需要在跟 package.json 中添加 lint-staged ，执行命令需要使用 --filter 来指定 package。 下面是对所有的package执行命令

```json
"lint-staged": {
  "*.{vue,js,jsx,ts,tsx}": [
    "pnpm --filter * run format",
    "pnpm --filter * run lint:fix"
  ]
},
```

- 3、husky 中创建 pre-commit 文件 

```sh
echo "pnpm exec lint-staged" > .husky/pre-commit
```

- 4、 测试

```js
// 在 main.ts 中添加了一段无用代码，如下
const a = 1;
// 在 app.vue 中代码中修改下格式，比如换行

git add .
git commit -m 'xx:xx'
// 出现下面的报错信息。
// 4:7  error  'a' is assigned a value but never used  @typescript-eslint/no-unused-**vars**
// 去掉 const a = 1; 再次提交
git commit -m 'xx:xx'
// 会出现下面错误，但是我们刻意错误格式化的代码，已经被 prettier 修复了
// ⧗   input: xx:xx
// ✖   subject may not be empty [subject-empty]
// ✖   type may not be empty [type-empty]

// ✖   found 2 problems, 0 warnings

git commit -m 'feat: add lint-staged'
// 提交成功， lint-staged 配置成功
```

## Changelog

- 1、安装依赖

```sh
pnpm add -w -D standard-version
```

- 2、编辑 package.json

```json
"scripts": {
  "release": "standard-version",
  "release:major": "standard-version --release-as major",
  "release:minor": "standard-version --release-as minor",
  "release:patch": "standard-version --release-as patch"
},
"standard-version": {
  "types": [
    {"type": "feat", "section": "✨ Features"},
    {"type": "fix", "section": "🐛 Bug Fixes"},
    {"type": "perf", "section": "⚡ Performance Improvements"},
    {"type": "revert", "section": "⏪ Reverts"},
    {"type": "docs", "section": "📝 Documentation"},
    {"type": "style", "section": "💄 Styles"},
    {"type": "refactor", "section": "♻️ Code Refactoring"},
    {"type": "test", "section": "✅ Tests"},
    {"type": "build", "section": "📦 Build System"},
    {"type": "ci", "section": "👷 Continuous Integration"}
  ]
}
```

- 3、初始化项目
  - 1、修改版本号，例如 1.0.0
  - 2、生成 changelog.md ; `pnpm run release --skip.bump`  默认会升版本号，这里仅生成文件
  - 3、提交代码

- 4、版本迭代
  - 1、`git commit -m 'feat: xxx1' `
  - 2、`git commit -m 'feat: xxx2' `
  - 3、`pnpm run release:minor` 升版本号，根据实际情况选择 major,minor,patch
  - 4、`git push ..` 推送代码

- 5、changelog.md 文件内容

```md
# Changelog

All notable changes to this project will be documented in this file. See [standard-version](https://github.com/conventional-changelog/standard-version) for commit guidelines.

## [1.1.0](https://xxxxx) (2025-05-20)


### ✨ Features

* add xxx1 ([9999999](https://xxxx))
* add xxx2 ([9999998](https://xxxx))

## 1.0.0 (2025-05-20)


### ✨ Features

* add test1 ([8888888](https://xxxx))
* add test2 ([8888887](https://xxxx))
```
